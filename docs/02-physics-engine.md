# PRD 02 — 물리 엔진

이 프로젝트의 핵심이다. 다른 모든 기능(리플레이, 온라인 검증, AI)이 이 코어를 그대로 재사용한다.

## 1. 목표

- 실제 당구에서 관찰되는 현상을 빠짐없이 재현한다.
- 같은 입력에 항상 같은 결과를 낸다(결정적).
- 한 샷을 수 밀리초 안에 계산한다(AI가 한 턴에 수천 번 호출).
- 렌더링·UI와 완전히 분리된 순수 TypeScript 라이브러리로 만든다.

## 2. 재현해야 하는 현상

| 분류 | 현상 | 원인이 되는 물리 |
|---|---|---|
| 큐-공 | 밀어치기, 끌어치기, 죽여치기 | 당점 상하에 따른 전진·후진 회전 |
| 큐-공 | 스쿼트(큐볼이 당점 반대쪽으로 밀려남) | 큐 끝 유효 질량 |
| 큐-공 | 미스큐(큐미스) | 당점이 한계(약 0.5R)를 넘거나 초크 부족 |
| 큐-공 | 타법 차이 | 임팩트 속도, 가속도, 접촉 시간, 팁 경도 |
| 고각 | 스워브(살짝 휨), 마세(크게 휨) | 수평축 회전 + 미끄럼 마찰 |
| 고각 | 점프 | 수직 속도 성분, 바닥 반발 |
| 공-바닥 | 미끄럼 → 구름 전환, 감속 | 미끄럼 마찰, 구름 저항 |
| 공-바닥 | 제자리 회전 감쇠 | 수직축 회전 마찰 |
| 공-공 | 분리각 (90° 법칙, 30° 법칙) | 탄성 충돌 + 충돌 후 회전에 의한 휨 |
| 공-공 | 스로우(두께가 틀어짐), 회전 전달 | 공-공 마찰 |
| 공-공 | 킥(초크 자국으로 튐) | 국소적 마찰 증가 |
| 공-쿠션 | 회전에 따른 반사각 변화 (순회전은 길게, 역회전은 짧게) | 쿠션 접점의 마찰과 접촉 높이 |
| 공-쿠션 | 강하게 치면 각이 짧아짐 | 쿠션 압축의 속도 의존 |
| 공-쿠션 | 쿠션에서 회전 변화 | 접점 미끄럼 |
| 환경 | 천 속도, 습도, 새 공, 테이블 기울기 | 계수 변화, 중력 경사 성분 |

## 3. 공의 운동 상태

| 상태 | 조건 | 운동 |
|---|---|---|
| 정지 | 속도·회전 모두 0 | 없음 |
| 제자리 회전 | 속도 0, 수직축 회전만 | 회전이 일정하게 감쇠 |
| 미끄럼 | 접점의 상대 속도가 0이 아님 | 일정한 마찰 가속 → 궤적이 포물선 |
| 구름 | 접점 상대 속도 0 (v = Rω) | 직선 감속 |
| 공중 | 바닥에서 떨어짐 | 포물선 비행, 착지 시 반발 |

핵심 관계식 [지식, 구현 시 재유도]:
- 접점 상대 속도: u = v + R(k × ω)
- 미끄럼 지속 시간: t = 2|u₀| / (7 μs g)
- 회전 없이 출발한 공이 구름에 도달했을 때 속도: 처음의 5/7
- 미끄럼 구간 궤적은 포물선, 이후 직선 구름 [확인, Coriolis/Alciatore]

## 4. 충돌 모델

### 4.1 큐-공

- 기본: 임펄스 모델 + 스쿼트 계산 (Alciatore TP A-30) [확인].
- 중심 타격 시 공 속도: v = V(1 + e) / (1 + m공/m큐).
- 당점이 중심에서 벗어날수록 속도는 줄고 회전이 생긴다. 회전량은 대략 ω = 5vb / (2R²) (b는 당점 거리).
- 큐 고각이 있으면 임펄스의 수직 성분이 생긴다. 바닥이 받아내는 양을 넘으면 점프가 된다.
- **타법 모델**: 팁-공 접촉을 유한 시간(0.8~3ms [확인])의 스프링-댐퍼로 계산하는 정밀 모드를 둔다. 입력은 임팩트 속도, 임팩트 순간 가속도, 팁 경도, 큐 질량. 접촉 시간이 길면 유효 당점이 약간 커지고 스쿼트도 함께 커진다 [확인].
- 미스큐: 당점 거리와 팁 마찰(초크 상태)로 판정. 한계를 넘으면 미끄러진 타격으로 처리.

참고: 팔로스루와 그립 세기는 접촉에 유의미한 영향이 없다는 것이 측정 결과다 [확인]. 따라서 이들은 물리 입력이 아니라 스트로크 정확도 쪽에서 다룬다(PRD 03).

### 4.2 공-공

- 마찰이 있는 비탄성 충돌. Mathavan 2014 또는 Alciatore의 마찰 임펄스 모델 [확인].
- 공-공 마찰은 접점 상대 속도에 따라 변한다(느릴수록 커짐) [지식].
- 스로우, 회전 전달, 충돌 후 휨이 모델에서 자연히 나와야 한다.
- 킥: 낮은 확률로 접점 마찰을 크게 올리는 옵션(기본 꺼짐, 환경 설정).
- 여러 공 동시 충돌(포켓볼 브레이크): 미세한 시간차로 순차 처리. 2단계에서 정밀화.

### 4.3 공-쿠션

- 기본: Mathavan 2010. 쿠션 접점과 바닥 접점의 미끄럼을 동시에 계산하고 압축·복원 단계를 수치 적분 [확인].
- 대안·비교용: Han 2005 (해석적, 빠름) [확인]. AI의 대량 탐색에는 Han을 쓰고 최종 실행은 Mathavan으로 하는 구성을 검토.
- 입력: 입사 속도, 3축 회전, 쿠션 접촉 높이, 쿠션 마찰, 반발계수.
- 반발계수는 입사 속도에 따라 변하게 한다(강하게 치면 더 많이 죽음) [지식].
- 캐롬 테이블의 쿠션 높이와 탄성은 포켓 테이블과 다르다. 종목별 테이블 프로파일로 분리.

### 4.4 공-바닥 (점프 후)

- 수직 반발계수 약 0.5 [초기값]. 착지 순간의 회전과 마찰로 수평 속도 변화.
- 테이블 밖으로 나가면 장외 처리.

## 6. 수치 해석

- **이벤트 기반 해석적 방식**을 쓴다 (Leckie & Greenspan 2006) [확인].
  - 각 상태의 운동은 시간의 2차식이다. 다음 이벤트(충돌, 상태 전이) 시각을 4차 이하 다항식의 근으로 정확히 구한다.
  - 고정 타임스텝의 터널링·오차 누적이 없다.
- 이벤트 종류: 공-공 충돌, 공-쿠션 충돌, 미끄럼→구름, 구름→정지, 회전 정지, 착지, (포켓) 낙하.
- 4차 방정식 풀이는 수치 안정성이 중요하다. 해석해 + 뉴턴 보정을 쓰고, 근접·접촉 상태의 예외를 따로 처리한다.
- 출력: 이벤트 목록과 구간별 운동식. 렌더러는 이를 받아 임의 시각의 위치·회전을 계산한다(리플레이, 슬로모션에 그대로 사용).

## 7. 결정성

- 같은 초기 상태 + 같은 샷 입력 → 비트 단위로 같은 결과.
- 사칙연산과 제곱근은 IEEE 754로 일치하지만, `Math.sin` 등은 브라우저마다 다를 수 있다. 삼각함수 등은 자체 구현을 쓴다.
- 난수는 시드 고정 생성기만 사용.
- 샷 결과에 상태 해시를 붙여 클라이언트·서버 불일치를 감지한다.

## 8. 인터페이스 (개념)

```ts
simulate(table: TableProfile, balls: BallState[], shot: ShotInput): ShotResult

ShotInput  = { 방향, 큐 고각, 당점(x, y), 임팩트 속도, 임팩트 가속도, 큐 사양 }
ShotResult = { events[], 구간별 운동식, 최종 BallState[], 상태 해시 }
```

## 10. 성능 목표 [초기값]

- 캐롬 한 샷(공 3~4개): 1ms 이내 (Han 쿠션 기준), Mathavan 사용 시 5ms 이내.
- AI 탐색은 Web Worker에서 실행.

## 11. 미결 사항

- Mathavan 쿠션 모델의 상수 튜닝 (참고 구현들도 미완 상태 [확인])
- 캐롬 쿠션의 실측 데이터 확보 방법
- 정밀 타법 모델(스프링-댐퍼)의 파라미터 출처
