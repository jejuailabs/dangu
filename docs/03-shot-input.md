# PRD 03 — 샷 입력과 타법

물리가 아무리 정교해도 입력이 "파워 게이지"면 타법 차이는 사라진다. 이 문서는 사용자의 손동작을 물리 입력으로 바꾸는 방법을 정의한다.

## 1. 목표

- 강하게 끊어치는 것과 부드럽게 밀어치는 것이 실제로 다른 결과를 낸다.
- 큐를 세워 치는 동작(고각)을 연속적으로 조절할 수 있다.
- 초보자는 쉽게, 상급자는 정밀하게 칠 수 있다.
- 마우스와 터치 모두에서 동작한다.

## 2. 샷의 구성 요소

| 요소 | 범위 | 물리 입력 |
|---|---|---|
| 조준 방향 | 0~360° | 큐 수평 방향 |
| 당점 | 공 중심 기준 (x, y), 최대 약 0.5R | 타격 오프셋 → 회전 |
| 큐 고각 | 0~90° | 임펄스의 수직 성분 → 스워브, 마세, 점프 |
| 임팩트 속도 | 0~약 10 m/s | 공의 속도 |
| 임팩트 가속도 | 스트로크에서 측정 | 접촉 시간·유효 당점 미세 변화 |
| 스트로크 직진성 | 스트로크에서 측정 | 조준·당점 오차 |

## 3. 입력 흐름

1. **조준**: 마우스 이동 또는 드래그로 큐 방향 회전. 미세 조정 키(느린 회전) 제공.
2. **당점**: 공 확대 그림에서 클릭 또는 드래그. 미스큐 위험 영역을 색으로 표시.
3. **고각**: 휠 또는 슬라이더. 주변 공이나 쿠션 때문에 큐가 물리적으로 걸리면 최소 고각을 자동 적용(실제처럼 레일 근처에서는 큐를 들어야 한다).
4. **스트로크**: 아래 방식 중 선택.
5. **실행**: 임팩트 순간의 값이 물리 코어로 전달된다.

## 4. 스트로크 방식

### 4.1 스트로크 모드 (기본, 타법 반영)

- 마우스 버튼을 누른 채 뒤로 당겼다가 앞으로 민다. 터치는 드래그.
- 포인터 위치를 시간과 함께 샘플링한다(브라우저의 고해상도 포인터 이벤트 사용).
- 가상의 팁이 공 표면에 닿는 순간을 임팩트로 본다. 그 시점에서 다음을 계산한다.

| 측정값 | 계산 | 영향 |
|---|---|---|
| 임팩트 속도 | 접촉 직전 구간의 속도 | 공 속도 |
| 임팩트 가속도 | 접촉 직전 속도 변화 | 가속 중이면 "밀어치기", 감속·정지 중이면 "끊어치기" 성향 |
| 좌우 흔들림 | 스트로크 축에서 벗어난 정도 | 조준과 당점에 오차로 반영 |
| 백스윙 길이 | 당긴 거리 | 표시용, 낼 수 있는 최대 속도의 상한 |

- 화면 이동 거리 → 큐 이동 거리 환산 비율(감도)은 설정에서 조절.
- 임팩트 후에도 큐 애니메이션은 사용자의 움직임을 따라간다(팔로스루 표현). 물리에는 영향 없음.

### 4.2 타법이 결과에 미치는 경로

실측 연구에 따르면 팁 접촉은 1~2ms로 매우 짧고, 팔로스루 자체는 공에 영향을 주지 못한다 [확인]. 그래서 타법 차이는 다음 경로로 구현한다.

1. **임팩트 속도 차이** — 가장 큰 요인. 같은 "세기"라도 스트로크 형태에 따라 실제 속도가 달라진다.
2. **임팩트 가속도** — 가속하며 맞으면 접촉 시간이 약간 길어지고 유효 당점이 조금 커진다. 감속하며 맞으면 반대. 효과는 작지만 정밀 모델에서 반영한다.
3. **정확도** — 빠르고 급한 스트로크일수록 좌우 흔들림이 커진다. 사용자의 실제 손 움직임에서 나오므로 인위적 난수가 필요 없다.
4. **팁·큐 사양** — 부드러운 팁은 접촉 시간이 길다. 큐 종류 선택으로 반영(성능 우열이 아닌 특성 차이).

결과적으로 "밀어치기"는 길고 가속하는 스트로크, "끊어치기"는 짧고 빠르게 멈추는 스트로크로 사용자가 직접 구사하게 된다.

### 4.3 게이지 모드 (보조)

- 속도를 슬라이더로 정하고 버튼으로 실행. 가속도는 0, 흔들림 없음.
- 초보자, 접근성, 정밀한 연습용.
- 온라인 대전에서는 방 설정으로 허용 여부를 정한다(스트로크 모드와 섞이면 공정성 문제).

### 4.4 수치 입력 모드 (연습 전용)

- 방향, 당점, 고각, 속도를 숫자로 직접 입력. 같은 샷을 반복 실험할 때 사용.

## 5. 보조 기능

| 기능 | 내용 | 기본값 |
|---|---|---|
| 조준선 | 큐볼 진행 방향 직선 | 켜짐 |
| 1차 예측선 | 첫 충돌까지의 경로와 분리 방향 | 초보 켜짐 |
| 전체 예측선 | 물리 코어로 계산한 전체 경로 (현재 당점·속도 기준) | 연습 모드만 |
| 두께 표시 | 수구와 목적구의 겹침 정도 (1/2, 1/4 등) | 켜짐 |
| 다이아몬드 번호 | 쿠션 포인트 수치 표시 (시스템 연습) | 선택 |
| 미스큐 경고 | 당점 한계 표시 | 켜짐 |
| 스트로크 피드백 | 방금 스트로크의 속도, 가속도, 흔들림 수치 | 켜짐 |

- 대전에서는 방 설정으로 보조 수준을 통일한다.
- 예측선은 스쿼트·스워브를 포함해 실제 물리 결과를 보여준다(단순 직선이 아님).

## 6. 마세·점프 입력

- 고각 45° 이상에서는 화면을 위에서 내려다보는 전용 시점으로 전환.
- 당점은 위에서 본 공 그림에서 선택.
- 스트로크는 동일하게 당겼다 미는 동작. 고각이 클수록 흔들림의 영향이 크게 나타난다(실제 난이도 반영).
- 실제 당구장 예절과 달리 천 손상 페널티는 없음.

## 7. 모바일

- 한 손 조작 기준. 조준은 화면 드래그, 당점·고각은 패널, 스트로크는 전용 영역에서 아래로 당겼다 위로 밀기.
- 터치 샘플링이 낮은 기기에서는 속도 추정 구간을 넓혀 보정.

## 8. 확장 여지

- 입력 계층은 "ShotInput을 만들어내는 장치"로 추상화한다. 추후 휴대폰 자이로 스트로크, VR 컨트롤러, 실제 큐 센서를 붙일 수 있게 한다.

## 9. 요구사항 요약

- [ ] 스트로크 모드에서 같은 최대 속도라도 가속·감속에 따라 결과가 달라질 것
- [ ] 스트로크 직후 속도·가속도·흔들림 수치를 표시할 것
- [ ] 큐가 공·쿠션에 걸리는 경우 최소 고각을 강제할 것
- [ ] 세 가지 스트로크 방식을 설정에서 전환할 수 있을 것
- [ ] 모든 방식이 동일한 ShotInput 형식을 만들 것

## 10. 미결 사항

- 마우스 감도 기본값과 기기별 보정 방법
- 스트로크 흔들림을 오차로 환산하는 비율 (플레이 테스트로 결정)
- 게이지 모드와 스트로크 모드 간 대전 공정성 처리
