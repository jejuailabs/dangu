# PRD 06 — 멀티플레이

## 1. 목표

- 한 기기에서 번갈아 치는 대전과 온라인 대전을 모두 지원한다.
- 클라이언트를 조작해도 결과를 바꿀 수 없다.
- 네트워크가 느려도 플레이 감각이 유지된다.

## 2. 대전 방식

| 방식 | 설명 | 서버 필요 |
|---|---|---|
| 로컬 대전 | 한 화면에서 번갈아 침. 2~4인 | 아니오 |
| 친구 대전 | 방을 만들고 링크 공유 | 예 |
| 빠른 대전 | 수지 기반 자동 매칭 | 예 |
| 관전 | 진행 중인 방을 링크로 시청 | 예 |
| 컴퓨터 대전 | PRD 05 | 아니오 (기록 저장 시 예) |

## 3. 동기화 구조

당구는 턴제이고 물리가 결정적이므로, **샷 입력값만 주고받는다.**

```
치는 사람 클라이언트
  ① 샷 입력 완료 → ShotInput 전송
서버
  ② 차례·시간·입력 범위 확인
  ③ 물리 코어로 직접 시뮬레이션 → 결과와 판정 확정
  ④ ShotInput + 결과 해시를 모든 참가자·관전자에게 전송
모든 클라이언트
  ⑤ 같은 ShotInput으로 로컬 시뮬레이션 → 애니메이션 재생
  ⑥ 해시가 다르면 서버가 보낸 최종 상태로 교정
```

- 전송 데이터는 샷당 수십 바이트 수준이다.
- 치는 사람은 서버 응답을 기다리지 않고 바로 자기 화면에서 재생한다(지연 체감 없음). 서버가 거부하는 경우에만 되돌린다.
- 조준 중인 큐의 움직임은 낮은 빈도(초당 10회 정도)로 중계해 상대가 볼 수 있게 한다.

## 4. 공정성

| 위협 | 대응 |
|---|---|
| 결과 조작 | 서버가 결과를 직접 계산. 클라이언트 결과는 표시용 |
| 불가능한 입력 (과도한 속도, 범위 밖 당점) | 서버가 ShotInput 범위 검증 |
| 자동 조준 프로그램 | 결과 조작은 불가능하나 입력 보조는 가능. 스트로크 궤적 데이터의 통계적 이상 탐지, 신고와 리플레이 검토로 대응 |
| 예측선 변조 | 예측선은 물리 코어가 공개되어 있어 막기 어렵다. 방 설정의 보조 수준이 사실상 상한이라는 점을 감안해 랭크전 보조 수준을 정한다 |
| 고의 접속 종료 | 재접속 대기 시간 후 패배 처리 |
| 시간 끌기 | 샷 제한 시간, 누적 지연 경고 |

- **능력치 과금 없음.** 큐·장비는 방 설정으로 통일하거나 특성만 다르다.
- 모든 대전은 리플레이가 서버에 남아 사후 검증이 가능하다.

자동 조준 대응의 한계: 물리가 결정적이고 코드가 브라우저에 있으므로, 외부 프로그램이 최적 샷을 계산하는 것 자체는 막을 수 없다. 스트로크 모드에서는 계산된 샷을 손으로 정확히 실행해야 하므로 영향이 줄어든다. 랭크전은 스트로크 모드 전용으로 하는 것을 기본안으로 한다.

## 5. 방 설정

- 종목, 테이블 프로파일, 목표 점수와 핸디
- 하우스 룰 (PRD 04)
- 스트로크 방식 허용 범위 (스트로크 전용 / 게이지 허용)
- 보조 기능 수준 (조준선만 / 1차 예측선 / 없음)
- 샷 제한 시간, 타임아웃
- 관전 허용 여부, 비공개 방

## 6. 매칭과 수지

- 계정마다 종목별 수지를 둔다. 처음에는 자기 신고 또는 AI와의 배치 경기로 정한다.
- 경기 결과와 에버리지로 수지를 자동 조정한다. 급격한 변동을 막기 위해 최근 N경기 기준.
- 빠른 대전은 가까운 수지끼리 매칭하고, 차이가 나면 핸디(목표 점수 차등)를 자동 적용한다.
- 랭킹: 종목별, 수지 구간별.

## 7. 접속 문제 처리

| 상황 | 처리 |
|---|---|
| 일시 끊김 | 서버가 방 상태 유지, 재접속 시 현재 상태와 지난 샷 목록 전송 |
| 재접속 대기 초과 (기본 60초 [초기값]) | 기권 처리 |
| 샷 전송 중 끊김 | 서버 수신 여부 기준. 미수신이면 재접속 후 다시 침 |
| 서버 장애 | 방 상태를 주기적으로 저장, 복구 후 재개 |

방 상태 = 초기 배치 + 샷 입력 목록. 이것만 있으면 언제든 현재 상태를 재현할 수 있다.

## 8. 소통

- 정해진 문구와 이모티콘 (기본)
- 자유 채팅은 친구 대전에서만, 신고·차단 제공
- 관전자 채팅은 선수 화면에 표시하지 않음

## 9. 계정

- 비로그인: 로컬 대전, 컴퓨터 대전, 연습, 친구 대전 참가(임시 이름) 가능. 기록은 브라우저에 저장.
- 로그인: 빠른 대전, 랭킹, 기록 동기화, 대시보드.
- 로그인 방식은 소셜 로그인 위주 [미결].

## 10. 요구사항 요약

- [ ] 로컬 대전이 서버 없이 동작할 것
- [ ] 온라인 대전에서 서버가 모든 샷 결과를 재계산할 것
- [ ] 클라이언트·서버 해시 불일치 시 서버 상태로 교정할 것
- [ ] 끊김 후 재접속으로 경기를 이어갈 수 있을 것
- [ ] 관전자가 지연 없이(샷 단위) 볼 수 있을 것
- [ ] 모든 온라인 경기의 리플레이가 저장될 것

## 11. 미결 사항

- 로그인 제공자, 개인정보 처리 방침
- 랭크전의 보조 기능 수준
- 수지 자동 조정 공식
- 서버 규모와 비용 (PRD 09)
