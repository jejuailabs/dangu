# PRD 10 — 로드맵과 검증

## 1. 마일스톤

각 단계는 "실행해서 확인할 수 있는 결과물"로 끝난다. 기간은 정하지 않았다(작업 방식에 따라 크게 달라짐).

### M0 — 물리 코어
- 결정적 수학 함수, 4차 방정식 풀이
- 5개 운동 상태와 전이
- 큐-공(스쿼트, 고각), 공-공(마찰), 공-쿠션(Han → Mathavan), 점프
- 이벤트 기반 진행
- 2D 디버그 뷰어
- **완료 기준**: 2절의 물리 검증 테스트 전부 통과, 브라우저 간 해시 일치

### M1 — 혼자 치기
- Three.js 테이블·공·큐, 조명, 카메라
- 조준, 당점, 고각, 스트로크 입력 (3가지 방식)
- 3쿠션·4구 규칙 판정
- 연습 모드 기본 (자유 배치, 되돌리기, 예측선)
- **완료 기준**: 브라우저에서 3쿠션·4구를 혼자 끝까지 칠 수 있음. 타법에 따라 결과가 달라짐

### M2 — 기록과 로컬 대전
- 스코어보드 (점수, 이닝, 런, 에버리지, 하이런)
- 리플레이 저장·재생, 즉시 리플레이, 오버레이
- 경기 기록지
- 로컬 대전
- 브라우저 저장
- **완료 기준**: 두 사람이 한 기기로 경기하고, 끝난 뒤 기록지와 리플레이를 볼 수 있음

### M3 — 컴퓨터 상대
- 샷 후보 생성, 평가, 수지별 오차
- 자동 대국 보정 도구
- 4구 13단계, 3쿠션 단계
- **완료 기준**: 단계별 에버리지가 단조 증가하고 목표 범위에 듦. 테스터가 단계 차이를 체감

### M4 — 온라인
- 서버, 방, 샷 검증, 재접속
- 계정, 기록 동기화
- 친구 대전, 관전, 빠른 대전, 랭킹
- **완료 기준**: 서로 다른 기기·브라우저에서 경기가 어긋남 없이 끝남. 조작된 클라이언트의 결과가 반영되지 않음

### M5 — 대시보드와 분석
- 개인 대시보드 (추이, 전적)
- 샷 유형 분류, 실패 원인, 약점 진단
- 클립 공유, 훈수 모드
- **완료 기준**: 사용자가 자기 약점 유형을 확인하고 해당 연습 과제로 이동할 수 있음

### M6 — 포켓볼
- 포켓 형상과 낙하, 브레이크 다중 충돌
- 8볼, 9볼 규칙
- 포켓볼용 AI

### 의존 관계

```
M0 ─▶ M1 ─▶ M2 ─▶ M3
              └──▶ M4 ─▶ M5
M1 ─────────────────────▶ M6
```

M3과 M4는 M2 이후 병행 가능.

## 2. 물리 검증 테스트

| 번호 | 테스트 | 기대 결과 |
|---|---|---|
| P1 | 회전 없이 출발한 공 | 구름 도달 시 속도가 초기의 5/7 |
| P2 | 미끄럼 지속 시간 | 2u₀ / (7μg)와 일치 |
| P3 | 구르는 공의 정지 거리 | v² / (2μr g)와 일치 |
| P4 | 스턴 샷 분리각 | 수구와 목적구가 약 90° (반발계수·마찰 보정 포함) |
| P5 | 구름 상태 수구의 분리각 | 넓은 두께 범위에서 약 30° 휨 |
| P6 | 끌어치기 | 정면 충돌 후 수구 후진, 후진 거리가 회전량에 비례 |
| P7 | 스로우 | 회전 준 수구가 목적구를 회전 반대 방향으로 미세하게 틀음. 느릴수록 큼 |
| P8 | 스쿼트 | 옆 당점에서 수구가 당점 반대쪽으로 밀려남. 큐 유효 질량에 따라 변함 |
| P9 | 스워브·마세 | 고각 + 옆 당점에서 미끄럼 구간 포물선, 이후 직선. 최종 방향이 Coriolis 작도와 일치 |
| P10 | 점프 | 고각과 속도가 임계를 넘을 때만 발생, 비행 궤적 포물선 |
| P11 | 쿠션 반사 (무회전) | Mathavan 2010 그래프의 반사각·속도와 일치 |
| P12 | 쿠션 반사 (회전) | 순회전은 각이 길어지고 역회전은 짧아짐. 논문 수치와 비교 |
| P13 | 쿠션 속도 의존 | 강하게 칠수록 반사각이 짧아짐 |
| P14 | 에너지 | 어떤 충돌에서도 총 운동 에너지가 늘지 않음 |
| P15 | 결정성 | 무작위 1만 샷의 해시가 모든 환경에서 일치 |
| P16 | 경계 상황 | 붙은 공, 쿠션에 붙은 공, 구석, 동시 충돌에서 멈춤·무한 반복 없음 |
| P17 | 테이블 기울기 | 기울기 설정 시 구르는 공이 예상 방향으로 휨 |
| P18 | 타법 | 같은 최대 속도에서 가속·감속 스트로크의 결과 차이가 모델 예측 범위 내 |

교차 검증: 같은 조건의 샷을 pooltool로 실행해 비교한다.

## 3. 그 외 테스트

| 영역 | 방법 |
|---|---|
| 규칙 | 이벤트 목록 → 판정의 단위 테스트. 득점·파울 사례 모음 |
| 리플레이 | 저장 → 불러오기 → 재생 결과가 원본과 일치. 구버전 코어 리플레이 재생 |
| AI | 자동 대국 통계 (에버리지, 하이런 분포, 단계 간 승률) |
| 네트워크 | 지연·끊김·순서 뒤바뀜 모의, 조작 클라이언트 모의 |
| 성능 | 샷 계산 시간, 프레임, 로딩 시간을 CI에서 측정해 퇴행 감지 |
| 브라우저 | Chrome, Firefox, Safari, 모바일 Chrome·Safari |
| 사용성 | 처음 접속한 사람이 1분 안에 첫 샷을 치는지 관찰 |
| 체감 | 동호인 테스터 평가 (수지별 최소 1명씩 권장) |

## 4. 위험 요소

| 위험 | 영향 | 대응 |
|---|---|---|
| 쿠션 모델 상수 튜닝 난항 | 3쿠션의 핵심 품질 저하 | Han 모델로 먼저 완성, Mathavan은 병행. 실측 영상으로 보정 |
| 4차 방정식 수치 불안정 | 충돌 누락, 멈춤 | 예외 상황 테스트(P16) 선행, 근 보정 |
| 브라우저 간 부동소수점 차이 | 온라인 어긋남 | 자체 수학 함수, 서버 정본, CI 해시 비교 |
| 스트로크 입력의 기기 편차 | 타법 재현 불균일 | 감도 보정 절차, 게이지 모드 대안 |
| 수지별 에버리지 자료 부재 | AI 단계 신뢰도 | 동호인 자료 수집, 테스터 피드백 반복 |
| 정밀 타법 모델의 파라미터 부족 | 타법 차이가 과장되거나 미미 | 측정 연구의 범위(접촉 0.8~3ms) 안으로 제한 |
| 자동 조준 프로그램 | 랭크전 신뢰 하락 | 스트로크 전용 랭크전, 이상 탐지, 리플레이 검토 |
| 범위 과다 | 완성 지연 | 마일스톤별 완료 기준 엄수, 포켓볼·분석은 후순위 |
| 그래픽 품질 기대 차이 | 재작업 | M1 초반에 화면 시안을 사용자에게 확인 |

## 5. 다음에 정할 것

PRD 전반의 미결 사항 중 개발 착수 전에 결정이 필요한 것:

1. 서비스 이름
2. 시각적 분위기 (사실적 당구장 / 깔끔한 스튜디오풍)
3. 한국식 4구 규칙 표준안과 3쿠션 단계표
4. UI 프레임워크 (React / Svelte)
5. 수익 모델 방향

M0(물리 코어)는 위 결정과 무관하게 바로 시작할 수 있다.
